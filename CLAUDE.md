# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

`AGENTS.md` is the primary contributor guide (structure, style, CI, security rules, commit format) and applies in full. This file adds commands and the cross-file architecture. The spec is `ventriloquist-tiktok-mcp-spec.md`; resolved decisions and deviations from it are in `docs/decisions.md`; operations are in `docs/runbook.md`.

## Commands

Run from the repo root (Node >= 22.13, pnpm 10.15.0). There is no linter, formatter or build step.

```bash
pnpm install
pnpm typecheck                 # tsc --noEmit across all three packages
pnpm test                      # every package's Vitest suite
pnpm smoke                     # mock signer + mock vendor + local Worker, drives real /mcp (needs no secrets)
pnpm migrate:local             # apply D1 migrations locally
pnpm dev                       # Worker on :8787; `pnpm signer:dev` for the signer (MOCK=1 offline)

# one file / one test
pnpm --filter @ventriloquist/worker exec vitest run test/velocity-math.test.ts
pnpm --filter @ventriloquist/worker exec vitest run -t "part of the test name"
pnpm --filter @ventriloquist/worker run test:watch
```

CI runs install --frozen-lockfile, typecheck, test, smoke. Use `MOCK=1` (signer) and `POSTING_DRY_RUN=1` (vps-agent) for any local work.

## Architecture

Three deployables, one trust chain: **Worker (Cloudflare) -> signer and vps-agent (VPS, behind Cloudflare Tunnel)**. The Worker is the only thing MCP clients talk to.

**Read path (GREEN/AMBER tools).** A tool handler in `worker/src/mcp/tools/*` asks `BackendRegistry` (`worker/src/backends/registry.ts`) for a *capability*, not a provider. The registry orders providers by cost (self-hosted signer, then Creative Center, then paid ScrapeBadger/ScrapeCreators), skips open circuit breakers (with a canary probe every 5 minutes), cascades on failure, trips a breaker after three consecutive *provider* faults, and drops paid providers once the daily budget is spent. Every attempt is emitted as a `provider_events` row, which is what the cost ledger is derived from. Successful responses are snapshotted into D1 (`worker/src/storage/`), and the velocity engine (`worker/src/velocity/`) works from those snapshots, so features like trend velocity depend on the cron jobs having accumulated history.

**Error classification matters.** `worker/src/lib/errors.ts` separates provider faults from bad input; only the former feed breakers. Handlers are wrapped by `wrapHandler` and never throw. Preserve this when adding tools or providers.

**Write path (RED posting).** Tool -> D1 `post_jobs` row -> Cloudflare Queue -> `worker/src/jobs/consumer.ts` -> POST to the vps-agent (Playwright, owns the posting session) -> agent calls back to the Worker's job-callback endpoint with the outcome. Properties spread across these files:

- Idempotency is per `job_id`: a queue retry replays the recorded outcome (`storage/jobs.ts`) rather than posting again. Terminal statuses are protected by `unlessTerminal` updates.
- Cap (5/day) and spacing (3h) are enforced structurally at validation time and re-checked at dispatch.
- The halt (two consecutive `failed` outcomes in 24h) is computed from D1 by `consecutivePostFailures`, with an operator clear time kept in KV. It is enforced both when queueing and in the consumer, where jobs that come due are marked `held` and must be re-queued after `POST /admin/posting/clear-halt`. `dry_run` and `held` rows never count toward or break a streak.
- Timestamps are Unix seconds; comparisons around the halt-clear boundary are deliberately inclusive (fail closed).

**Cron.** Seven jobs live in `worker/src/cron/`, dispatched by matching the cron string from `wrangler.toml`, so changing a schedule means editing both the trigger and the dispatcher key.

**Tests.** `worker/test/support/sqlite.ts` is a D1 stand-in on `node:sqlite` with all migrations applied; use it when correctness lives in SQL (it is why the Node floor is 22.13). `fakes.ts` provides fake Env/KV.

## Gotchas

- Three tokens must match across components or jobs are rejected: Worker `POSTING_WORKER_TOKEN` and `FACADE_CALLBACK_TOKEN`, VPS `FACADE_CALLBACK_TOKEN`. `/admin/*` and callbacks fail closed when their token is unset.
- No paid vendor key is provisioned and the 50-account shadow cohort is not seeded; `tt_system_status` reports both. This is intentional (see `docs/decisions.md`), not a bug to fix.
- `worker/.dev.vars` and `.wrangler-smoke/` are generated by `pnpm smoke` and gitignored; never commit them.
